# 能力契约

方法层用能力动词描述动作，适配层把它翻成具体平台的工具。**判断一句话属于哪一层的测试**：把平台名删掉，语义还成立 → 属方法层；删了就说不通 → 属适配层。

## 九个能力

| 能力 id | 语义要求 | 谁需要 | 不满足时的降级 |
|---|---|---|---|
| `load_rules` | 主执行能拿到本方法与项目约定 | 全部 | 手动把 `SKILL.md` 内容并入项目指令文件 |
| `spawn` | 派生独立上下文的执行，返回句柄 | 采集、写作、核查 | 在父上下文串行执行，但必须坚持"证据写文件、不读回原始页面" |
| `resume` | 用同一句柄继续同一执行（保留其状态） | 采集补采 | 单轮做完再收尾，扩大首轮 brief；不承诺增量，`context_kept: false` |
| `ask_human` | 由人回答阻塞问题 | 协调者 | 收集阻塞项，在返回里统一上报；不得由子执行直接问 |
| `fetch_static` | 取已知静态页并转成文本 | 采集、核查 | 全部走交互式取数 |
| `fetch_interactive` | 搜索、登录态、动态渲染、点击翻页、截图 | 采集 | 无法采集交互式来源，在 `failures` 记录并降级到静态可得来源 |
| `fs_scoped` | 在指定路径内读写文件 | 全部 | 只回传内容摘要，由父执行落盘（易丢证据，尽量补齐） |
| `check` | 执行本地脚本并按退出码判断 | 协调者、写作 | 按 `references/gates.md` 人工逐条核对，并在返回里注明"未经脚本验证" |
| `result` | 以固定字段回传结果，而不是过程噪声 | 全部 | 明确约定返回字段清单，禁止自由文本长跑 |

## 必须显式声明的平台事实

写适配文件时，下面五项不能靠猜，必须核对当前版本的文档或实际工具集：

1. 角色怎么声明（文件式 agent？prompt？profile 级 preset？）
2. 派生与续接的真实语义（同步返回？完成通知？能否带状态续接？）
3. 子执行能做什么、不能做什么（能否再派生、能否提问、审批怎么处理）
4. 文件写入的边界（沙箱范围、权限白名单）
5. 方法怎么被加载（技能机制？项目指令？手动粘贴？）

## 新建适配文件

`harness/<平台>.md` 至少包含五段，20–40 行即可：

```markdown
# <平台> 适配
## 加载方法        # load_rules 怎么实现
## 角色实例化      # roles/*.md 怎么变成该平台的 agent
## 派生与续接      # spawn / resume 的具体做法
## 取数与写文件    # fetch_* / fs_scoped
## 已知限制        # 不满足的能力 + 采用哪条降级
```

适配层只放"怎么做到"，**不得新增流程规则**。若某平台确实需要额外约束（例如子执行不能提问），把它写成"该平台上的限制 + 对应降级"，而不是改方法层。
