# DSH 适配

对应版本：DeepSeek Harness（本文件按 Desktop 0.2.x 的实测行为编写，换版本请复核工具可见性）。

## 加载方法（`load_rules`）

- 把本包放在 `<项目根>/.dsh/skills/research-workflow/`（项目根 = 最近的 `.git` 祖先目录），会话目录里会出现该技能，加载后正文注入当前执行。
- DSH 也会扫描 `<项目根>/.agents/skills/`（rank 200）与 `~/.dsh/skills/`，可用于跨项目复用。
- 项目约定写在仓库根 `AGENTS.md`，与方法冲突时以项目约定为准，并回头修正方法文件。

## 角色实例化

DSH **没有项目级 agent 文件**。角色只能通过两种方式落地：

1. **推荐**：派生时在 prompt 里写「先读 `roles/browser-collector.md` 并遵守，以下是本次 brief：…」。角色契约保持在单一文件，prompt 只带 brief。
2. 若某个角色长期高频使用，可做成 **Agent Preset**（由 bundle patch 声明，`plugin_manager` 安装，profile 级、影响所有会话、安装需要 Full access）。为一个项目的一次性角色不值得这么做。

## 派生与续接（`spawn` / `resume`）

- `spawn`：用子代理工具派发，返回一个句柄（子代理名称或 id，按当前版本字段）。子代理 prompt 必须**完全自包含**——它不继承本方法文件、不继承你的对话。
- `resume`：用消息工具对同一句柄继续发任务；已结束的子执行可被唤醒并保留原上下文。
- **续接优先于重派**：重新派生会丢掉浏览器态与登录态，补采必须续接同一句柄。只有续接报错（会话不可用）时才重派，并把已完成任务、证据、失败上下文、待办一并带上。
- 子执行的中间过程（快照、日志、DOM）不回流；回流的是结果文件路径 + 摘要。

## 取数与写文件（`fetch_*` / `fs_scoped`）

- `fetch_static`：内置网页抓取工具，适合已知静态 URL。
- `fetch_interactive`：走项目约定的浏览器通道（通常是先加载某个浏览器技能，再按其指南调用其命令行入口）。方法层不写工具名，具体通道由项目约定指定。
- `fs_scoped`：默认沙箱为工作区可写。**临时文件只写工作目录内指定路径或系统临时目录**；不要落在项目根或工作区外。
- 子执行内需要审批的操作会被拒绝——不要向子执行派发 `sudo`、装软件、写项目外路径这类任务。

## 已知限制

| 限制 | 影响 | 降级 |
|---|---|---|
| 子执行不能再派生 | 采集无法并行展开 | 一个采集执行串行跑完全部交互任务；静态任务由父级并行 |
| 子执行不能向用户提问 | 登录墙无法在子执行内解决 | 子执行回报阻塞项，由父级问用户；父级登录后**续接同一句柄**重采 |
| 子执行内审批自动拒绝 | 安装、跨目录写入不可用 | 只派项目内读写与浏览器调用 |
| 项目级无 agent 文件 | 角色不能按项目声明 | 角色随 prompt 传递（推荐）或 profile 级 preset（重） |
| 工具名随版本/配置变化 | 方法层写死会失效 | 方法层只写能力，工具名留本文件 |

## 一句话启动

> 读 `research-workflow/SKILL.md`，按六阶段执行；派采集时让它先读 `roles/browser-collector.md`；证据冻结前不要派写作。
