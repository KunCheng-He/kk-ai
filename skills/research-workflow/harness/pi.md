# Pi 适配

对应版本：`pi-k-subagent` 扩展（子代理以 Markdown 定义，每个子代理独立进程）。Pi 核心是否支持技能目录**未核实**——本文件按"有子代理、暂无技能机制"设计。

## 加载方法（`load_rules`）

- 没有技能机制时：把 `SKILL.md` 与项目约定一起并入项目指令文件（`AGENTS.md` 一类的入口），其余文件用相对路径引用。
- 不要假设"文件放在仓库里就会被自动读到"——是否加载取决于 Pi 的当前配置。

## 角色实例化

角色契约落成 `.pi/k-subagents/<name>.md`（项目级）或 `~/.pi/agent/k-subagents/<name>.md`（全局）：

```markdown
---
name: browser-collector
description: 交互式采集。隔离搜索与截图，只回传结构化证据与产物路径。
tools: read,bash,grep,edit,write
thinking: medium
---

遵守 <包路径>/roles/browser-collector.md 的全部约束。
本次 brief：
…
```

要点：

- `tools` 是白名单，相当于其他平台的权限边界；采集角色需要 `bash`（浏览器命令）与 `write`（证据文件），不需要不必要的工具。
- 正文引用 `roles/*.md`，不复制契约。
- `systemPromptMode: append`（默认）会保留输出约定；需要完全接管时用 `replace`，但要自行补回返回格式约束。

## 派生与续接（`spawn` / `resume`）

- `spawn`：用子代理工具，`agent` + `task` 单任务，或 `tasks[]` 并行（`concurrency` 控制）。
- **没有可靠续接**：每个子代理是独立进程，不保证能带状态继续。按"无 `resume`"设计：
  - 采集任务一次给全，brief 里写清"本轮即最终轮次"；
  - 需要补采时重新派发，并在 brief 里带上已完成的证据文件路径与待办清单；
  - 证据文件必须每轮写完并冻结，不依赖子会话记忆。
- 并行只用于相互独立的静态取数；交互式采集仍建议单任务串行，避免同一浏览器态冲突。

## 取数与写文件（`fetch_*` / `fs_scoped`）

- `fetch_static`：通过 `bash` 调本地抓取命令，或平台自带的抓取工具（按当前版本）。
- `fetch_interactive`：项目指定的浏览器通道，通过 `bash` 调用。
- `fs_scoped`：由 `tools` 白名单与工作目录共同约束；子代理不要写项目外路径。

## 已知限制

| 限制 | 影响 | 降级 |
|---|---|---|
| 无可靠续接 | 补采丢浏览器态，可能要重新登录 | 单轮采集 + 证据即时落盘 + 冻结后不追加 |
| 技能机制未核实 | 方法不能靠"自动加载" | 并入项目指令文件，或写进子代理定义 |
| 子代理是独立进程 | 中间态不回流 | 证据文件即接口，返回只给路径与摘要 |
| 并行度由扩展控制 | 可能被限流 | 减少并发、按批次派发 |

## 一句话启动

> 按项目指令文件里的 `research-workflow` 六阶段执行；采集用 `browser-collector` 子代理，一次给全 brief；证据冻结前不要派写作。
