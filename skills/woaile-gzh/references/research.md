# 调研报告模板与门禁

派报告执行者时把本文件一并给出。报告只读冻结后的证据，不再抓网页、不再补调研。

## 模板

```markdown
# {产品名称} 调研报告

> 调研时间：{YYYY-MM-DD HH:mm}
> 调研对象：{一句话定位}
> 产品类型：{类型}

## 摘要

**{结论 1 的判断句}。** {2–3 句支撑，数字具体}〔证据编号〕。

（共 4–6 条，每条一段，首句加粗；这是全文唯一必须「结论先行」的地方）

## 官方介绍

[核心定位、主要功能、目标用户、定价与差异化特点]

![{产品名称}产品图](素材/{实际截图文件名})
*图：{图片说明，含截取时间}*

## 优点

- **{判断}**。{细节}〔编号〕
- （3–5 条）

## 缺点

- **{判断}**。{细节}〔编号〕
- （3–5 条）

## 用户评价摘要

### 社区反馈亮点

- **{判断}**。{细节，注明平台、发布时间、互动数据}〔编号〕
- （每个平台至少 3 个独立内容 URL 才写满；不足时如实说明）

### 典型用户场景

[谁在使用、用于什么目的]〔编号〕

## 竞品对比

| 维度 | {产品} | {竞品1} | {竞品2} |
|------|--------|---------|---------|
| ... | ... | ... | ... |

> 本表证据：〔off-01、zhihu-02、…〕

[1–2 段解读，不要把长解释塞进单元格]

## 数据局限

- **{局限类别}**：{具体说明，含尝试过的来源与失败类型}

## 总结与建议

[是否值得关注、适合什么人群、作者的判断边界]

## 数据来源

### 官方

- `{id}` {来源}：{URL}（发布时间或抓取日期）

### 社区

- `{id}` {平台} - {标题}：{具体内容 URL}（发布时间、互动数据）

### 竞品

- `{id}` {竞品} - {维度}：{URL}
```

模板是骨架不是填空题：章节标题可按产品实际调整，但**顺序与层级不要变**；没有内容的章节合并或删除，不留空壳。

关键结论、数字、社区观点和竞品对比必须在对应句子或表格下方标注证据 ID（如 `[zhihu-01]`）；「数据来源」用相同 ID 列全信息，使正文结论可逐项追溯。

仅当截图路径真实存在时插入图片；没有截图就省略图片和图注，**不得引用占位文件名**。

## 版式规范（硬性）

1. **结构固定**：标题 → 背景块 → 摘要（4–6 条）→ 官方介绍 → 优点 → 缺点 → 用户评价 → 竞品对比 → 数据局限 → 总结 → 数据来源。不自创顺序，不把数据来源放前面。
2. **结论先行**：每节首句给判断，细节和数字随后。摘要每条写成「判断句 + 支撑句」，不写「本文介绍了……」「首先……其次……」。
3. **引用密度**：每个段落、每个列表项**最多一组**证据编号，放句末或段末，形如〔off-01、off-02〕。同一段多个 claim 共用一组；不要把编号插在词与词之间。表格证据单独成行。
4. **表格**：列数 ≤5，单元格 ≤25 字；需要长解释就挪到表格下方。
5. **段落与列表**：段落 ≤4 行；列表项 ≤3 行；统一「**判断**。解释〔编号〕」写法。
6. **图片**：正文配图 ≤3 张，紧跟相关段落；图注一行，只写「是什么 + 何时截取」；不用整页长截图。
7. **长度**：正文（不含数据来源）**不少于 1500 字**，不设上限；不得为凑字数重复观点或补写无证据内容。
8. **数据来源**：按官方 / 社区 / 竞品分组，社区再按平台分组；每条一行 `id · 日期 · 互动 · URL`；只放索引，不放分析。

## 写入前检查

1. 社区来源是具体内容 URL，不是首页、搜索页或关键词
2. 社区来源有发布时间；拿不到写「发布时间未获取」，不推测年份
3. 官方常青页没有发布时间时标注抓取日期
4. 至少 2 个竞品、3 个有证据支撑的对比维度
5. 价格、比例、互动量、Stars 等数字都能映射到输入证据
6. 图片路径相对报告所在目录可解析到真实文件
7. 所有失败或不足的数据源都在「数据局限」里，包括浏览器不可用导致的失败
8. 正文 ≥1500 字；抽查 5 个段落每段 ≤1 组证据编号；表格 ≤5 列、单元格 ≤25 字；配图 ≤3 张
9. 正文引用的每个 ID 都能在数据来源找到，数据来源的每个 ID 都能在输入证据找到，无「有引用无索引」「有索引无出处」
10. **证据必须已冻结**：`browser_results.md` 头部应为 `status: complete`。若为 `in_progress`、缺状态块、或条数与证据数不一致，视为未冻结——标题后标注「部分完成（证据冻结于 HH:MM）」，并在「数据局限」首条写明冻结时间与可能缺失的平台

**补采发生在初稿之后时**：不要只追加新段落，同步更新三处——正文样本量、「数据局限」中首轮结论是否被推翻、「数据来源」的条数与平台分组，避免口径打架。

门禁未通过时**不要自行补写或猜测缺失数据**：把失败项返回给主 Agent。只有主 Agent 确认无法补足并要求输出部分报告时，才标注「部分完成」并单列「数据局限」。
