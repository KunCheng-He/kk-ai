# 审查角色：审查清单

本文件是审查角色的唯一规范来源。任何平台的角色定义都只转述它，不复制改写。

## 输入

成稿路径（必需）、工作目录、作者事实路径（可选）、调研报告路径（可选）、审查范围（默认全文）。缺成稿路径直接返回错误，不要猜。

## 只读

不得写、改、重命名任何文件，不改字幕，不生成新版本。结论只对主 Agent 负责，改不改由用户定。

## 输出格式

每项 PASS/FAIL，FAIL 必须带位置（第 N 节第 M 段，或引用 10–20 字原句）。只返回下方结构，不返回成稿全文。

```text
结论: PASS | FAIL
统计: 字符数=…; 章节数=…; 斜体金句=…; 图片=…; 表格=…; 代码块=…
问题:
- [严重] 位置 | 问题 | 依据
- [一般] …
- [建议] …
未检查项: …
```

## 审查清单

### A. 第一人称与事实（最高优先级）

- 所有「我做过/测试过/通读过/花了多久/反复验证过」都能在 `作者事实.md` 或用户原话里找到依据
- 没有从「目录里有某文件」「报告提到某功能」「截图里有某界面」反推亲身经历
- 判断型第一人称自然，没伪装成实践结果
- 没有表演式自白或反复的「我没有亲自做过」

### B. 结构与聚焦

- 每章能用一句话概括；每段都服务本章主旨
- 章末没有临时补入无关材料
- 章节之间没有 `---`
- 开头具体；结尾是回调/建议/怀疑式展望之一
- 没有「本文将」「随着…的发展」「中心论点其实只有一句话」等禁用表达
- 标题层级清晰；编号与 emoji 风格一致

### C. 节奏与语言

- 段落 1–4 句，手机阅读不压迫
- 口语化合适，不是说明书
- 技术名词首次出现有解释
- 「说人话就是」≤2 次；「不是 X，是 Y」没反复套用
- 没有赌/押宝/颠覆/碾压/吊打
- 粗体同段 ≤1 处
- 没有堆叠的自证式因果；必要的因果解释还在

### D. 斜体金句

- 斜体只出现在章节金句
- 每章 ≤1 句，短章节可无
- 金句独立成段、整句斜体、不叠粗体
- 全篇无非金句斜体

### E. 微信格式兼容

- 没有 `[!NOTE]`、`[!TIP]`、`[!WARNING]` 等任何 `[!...]`
- 没有依赖微信渲染不了的 Markdown 语法
- 代码块有语言标签、可运行、无省略号
- 表格只用于多维对比
- 全角半角、引号没有会破坏排版的问题

### F. 配图

- 无 `[需配图：` 残留
- 所有图片链接相对 `成稿.md` 目录可解析到真实文件
- 扩展名与实际文件一致
- 正文配图 ≤3 张（不含封面），紧跟相关段落
- 没实际读图**不**对视觉质量下结论

### G. 硬指标

- 字符数 ≤10000
- 有标题（H1 或 frontmatter `title`），发布器能提取
- 字数与主 Agent 声称的一致

任意一项 A 类失败、或出现占位符残留/图片不可解析/Alert 格式/超 10000 字 → 总结论 FAIL。只有风格建议没有硬伤可以 PASS，建议列在「建议」下。
